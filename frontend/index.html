Auto-POJO Generation Pipeline
How it works
OpenAPI 3.0 Inference
The system fetches a live SAP API response and uses SapAutoServiceManager.java to infer an OpenAPI 3.0 specification from the JSON structure. Generated specs are written to the specs/ directory.
POJO Generation
OpenAPI Generator produces strongly-typed Java POJO models. Model classes are placed in service-specific packages under src/main/java/projectsap/sap/.
Dynamic DDL
DatabaseManager.ensureServiceTable() introspects the JSON structure and generates CREATE TABLE DDL with appropriate SQL types. A raw_json column always retains the full payload.

API Reference
REST endpoints implemented in BillServer.java. Server starts on port 8080 with automatic fallback to 8085, 8081, 8082, 8888.
GET /api/bills List stored bills with optional filters
Query Parameters
statusstringFilter by bill_status column value (e.g. OPEN, CLOSED)
typestringFilter by billing_type column value
currencystringFilter by currency column value (e.g. USD, EUR)
Response
[{ "id": "...", "billStatus": "OPEN", "currency": "USD", ... }]
GET /api/bills/{id} Fetch a single bill by ID
Path Parameters
idstringSAP bill identifier (URL-encoded if necessary)
Response
{ "id": "BILL-001", "billStatus": "OPEN", ... } // 404 if not found: { "error": "Bill not found with ID: ..." }

POST /api/services Register a new service
Request Body (JSON)
serviceIdstring *Service identifier (sanitized to lowercase alphanumeric + underscores)
displayNamestringHuman-readable name (defaults to "SAP - <serviceId>")
endpointstring *SAP API endpoint URL (also accepted as serviceUrl)
descriptionstringOptional description
syncNowbooleanWhether to fetch and store data immediately (default: true)
DEL /api/services/{serviceId} Unregister service and drop its table
Notes
The core bills service cannot be deleted. This operation drops the database table and removes the service from the runtime registry.
GET /api/data/{service} Get stored records for any service
Notes
Returns up to 500 records ordered by fetched_at DESC from the service's table. Each record is the raw_json field restored to its original structure. Returns [] if the table does not exist.
GET /api/fetch-log Synchronization audit log (last 50 entries)
Response Fields (per entry)
idnumberAuto-incremented log entry ID
fetchedAtstringTimestamp of the sync operation
billCountnumberNumber of records processed in this operation
statusstringSUCCESS or ERROR
messagestringHuman-readable operation summary or error message
POST /api/sync/{service} Trigger synchronization for a service
Notes
For the bills service, fetches from SapApiClient.fetchBillsFromSAP(). For other registered services, fetches from desc.getDefaultEndpoint(). Also accepts ?service=<name> query parameter if no path segment is provided. Returns { success, service, table, message, count }.
